# 长期记忆

> 让她记得你上次说过「喜欢淡一点的咖啡」——即使 `/reset` 过，即使隔了一个月。

一个给 AstrBot 用的插件。按 **QQ 号** 记住每个用户的稳定偏好，在聊天时悄悄带上。不额外调用模型，不花钱，也不给她加新工具。

---

## 三十秒上手

1. WebUI → 插件 → 安装插件
2. 插件列表里把「长期记忆」开关打开
3. 只想操作自己的记忆，到这一步就够了。要**查看/清除别人的**、或用 `/导出` `/导入` `/清空全部`，把 QQ 号填进 **配置 → `admins_id`**（群主身份不算）
4. 私聊她：「我喜欢淡一点的咖啡」
5. 发 `/记忆` —— 应该看到 `1. 喜欢淡一点的咖啡`

装完这几步就能用了，其余配置都有合理默认值。

---

## 她会记住什么

只记**稳定的、关于你本人的**偏好，分六类：

| 类型 | 触发句式 | 例子 | 记下来的样子 |
|---|---|---|---|
| 喜好 | 我喜欢 / 我爱 / 我偏爱 | 我喜欢淡一点的咖啡 | `喜欢淡一点的咖啡` |
| 厌恶 | 我不喜欢 / 我讨厌 / 我受不了 | 我不喜欢香菜 | `不喜欢香菜` |
| 称呼 | 我叫 / 你可以叫我 | 我叫小林 | `称呼：小林` |
| 住处 | 我住在 / 我家在 / 我是…人 | 我住在杭州 | `住在杭州` |
| 工作 | 我在…工作 / 上班 / 打工 | 我在字节工作 | `在字节工作` |
| 习惯 | 我每天 / 我一般 / 我习惯 | 我每天六点起床 | `每天六点起床` |

### 什么不记

下面这些是**故意**不记的，不是漏了：

| 不记 | 例子 | 原因 |
|---|---|---|
| 指代 | 我喜欢你 / 我喜欢这样 | 没有具体内容，记下来也没用 |
| 临时情绪 | 我讨厌今天 / 我不喜欢这个 | 明天就变了，记了是负担 |
| 转述 | 他说他喜欢咖啡 / 听说你喜欢 | 那不是说话人自己的偏好 |
| 第三人称 | 我朋友喜欢香菜 | 不该给她朋友建档 |
| 带数字的 | 我喜欢 2024 那年的豆子 | 宁可漏记，也不冒险把手机号、地址记进去 |
| 敏感词 | 身份证 / 密码 / 地址 / 工资 / 病历 | 隐私红线 |
| 疑问句 | 我喜欢什么呢 | 她自己在问，不是陈述 |

**一句话概括：宁可漏记，不可误记。** 记错了比没记住难受得多。

## 命令

权限分两级：**`/记忆` 和 `/忘记` 不带目标时人人都能操作自己**；带目标（QQ 号或 `@一个人`）时只有**超级管理员**（AstrBot 配置里 `admins_id` 的号）才能指向别人。`/导出`、`/导入`、`/清空全部` 仍然只给超级管理员。

| 指令 | 在哪用 | 谁能用 | 干什么 |
|---|---|---|---|
| `/记忆` | 私聊（群聊可选） | 所有人 | 看自己的记忆 |
| `/记忆 123456789` | 私聊（群聊可选） | 超级管理员（或本人报自己的号） | 看指定 QQ 的记忆 |
| `/记忆 @某人` | 私聊（群聊可选） | 超级管理员（或 @ 自己） | 看被 @ 那个人的记忆 |
| `/忘记` | 私聊（群聊可选） | 所有人 | 清空自己的记忆，真删 |
| `/忘记 123456789` | 私聊（群聊可选） | 超级管理员（或本人报自己的号） | 清空指定 QQ 的记忆 |
| `/忘记 @某人` | 私聊（群聊可选） | 超级管理员（或 @ 自己） | 清空被 @ 那个人的记忆 |
| `/导出` | **只能私聊** | 超级管理员 | 打包全部记忆，给一个下载链接 |
| `/导入` | **只能私聊** | 超级管理员 | 从上传的 zip 恢复记忆 |
| `/导入 合并` | **只能私聊** | 超级管理员 | 同上，但只增改不删人 |
| `/清空全部 确认` | **只能私聊** | 超级管理员 | 删光记忆 + 导出包 + 备份 |

> **`@` 怎么解析的**
>
> 目标优先级是 `@ 的人` > `纯数字参数` > `自己`，和 ranranbot_chatmanage 的 `pick_user_ids` 一致。QQ 号取自消息里的 At 段而不是文字——「@昵称」在文本里反查不到号。
>
> 一次只能 `@` 一个人，多了会拒绝（防止 `/忘记 @甲 @乙` 只删了甲却以为都删了）。`@全体成员` 和 `@机器人` 不算目标。
>
> 如果平台无法解析消息中的 `@` 段，插件不会把它当成空参数处理；请改用 `/记忆 <QQ号>` 或 `/忘记 <QQ号>`，避免误操作发送者自己的记忆。

> **为什么 `/导出` 和 `/导入` 永远不能在群里用**
>
> 下载链接等于一把钥匙，拿到的人不用登录就能下走全库数据。这个东西不该出现在群聊记录里。

### `/记忆` 长什么样

```
长期记忆（123456789 · 3 条）
1. 喜欢淡一点的咖啡 ×2
2. 不喜欢香菜
3. 称呼：小林
```

顺序是**按命中次数从多到少**，次数相同按记录的先后排。

`×2` 表示这个人一共说过两次同一件事。说得越多越不容易被淘汰，满三次就变成「常驻」，不再过期。

## 数据放在哪

```
<AstrBot 根目录>/data/plugin_data/astrbot_plugin_long_memory/
├── memory/
│   ├── 123456789.json      ← 一个人的全部记忆，一个文件
│   └── 10001.json
├── exports/                 ← /导出 生成的包，默认留 5 份 / 7 天
├── backups/                 ← 每次导入前自动备份一份
├── files/import_zip/        ← WebUI 上传的导入包，插件只读
└── state.json               ← 记录导入过哪些包，防重复导入
```

**为什么用文件而不是数据库**

- 你要能整包导出、整包塞回去，文件天然可以打包
- 出问题时用记事本打开就能看，不用连数据库
- 卸载时删掉这个目录就干净了，数据库里散落的记录做不到

**写得安全**：每次保存先写一个临时文件，落盘后再整体替换。断电、崩进程、磁盘满，最坏情况是「这次没写进去」，不会出现半个坏掉的 JSON 把之前的记忆一起带坏。

**出问题不会宕**：某个文件坏了，插件把它改名成 `xxx.json.corrupt.<时间戳>` 留着证据，然后当这个人没记忆处理。聊天照常，不会因为她读不到记忆就不回话。

## 导出：把记忆存下来

**第 1 步** 先在配置里填 `panel_base_url`，比如 `http://1.2.3.4:6185` 或 `https://bot.example.com`。不填也能导出，但回复里只有相对路径，得自己拼。

**第 2 步** 私聊发 `/导出`

```
已导出 3 人 / 42 条
long_memory_20261024_153012_8f3c1a.zip
1 小时内有效；拿到链接的人无需登录即可下载，别外传：
http://1.2.3.4:6185/api/file/8f3c1a9b2d...
```

**第 3 步** 点链接，浏览器直接下载。不用登录，不用输密码。

### 三件必须知道的事

**链接会过期。** 默认 1 小时，可在配置里改（`export_token_ttl`）。过期就重新 `/导出` 一次。

**AstrBot 一重启，所有链接立刻失效。** 凭证存在进程内存里，重启就没了。这不是 bug——真要持久化，等于在磁盘上留一张长期有效的门卡。重新导出即可。

**链接本身就是钥匙。** 拿到链接的人不需要登录就能下载整份记忆。包里是所有人的 QQ 号和偏好，本质是一份用户画像。别发群里，别丢公共网盘。

## 导入：把记忆放回去

**第 1 步** WebUI → 插件 → 长期记忆 → 配置 → 找到「导入包（zip）」→ 上传 → **点保存**

> **上传不等于保存**
>
> 上传完不点保存，文件虽然在盘上了，但插件不会重载，配置里也没有这个值。插件会扫目录兜底，但别指望它。

**第 2 步** 私聊发 `/导入` 或 `/导入 合并`

**第 3 步** 看回复

### 覆盖 vs 合并

| | 覆盖（默认） | 合并 |
|---|---|---|
| 包里有、本地没有 | 加进来 | 加进来 |
| 包里有、本地也有 | 以包为准 | 命中次数取较大值，不累加 |
| 包里有、本地是相反态度 | 以包为准 | 用较新的那条，删掉对立项 |
| **本地有、包里没有** | **删掉** | 保留 |
| 适合 | 恢复备份、换服务器 | 多台机器合流、只想补几条 |

**怎么选**：从备份恢复用覆盖；从另一台机器拿几条补充用合并。

> **覆盖很凶**
>
> 拿一个只有 3 个人的测试包去覆盖，剩下的用户会全部消失。所以做了三道保险——空包直接中止、导入前强制备份（备份失败就中止）、回复里明确写「删除本地 N 人」。

### 防呆机制

- **同一个包不会被导入两次**：记住每个包的指纹（sha256），第二次直接挡回去
- **目录里堆了旧包也不会选错**：按修改时间倒序，但跳过已经导入过的
- **包不合法整包拒绝**：不是本插件导出的、路径可疑的、带符号链接的、压缩比异常的，一律不读
- **单条坏了只丢单条**：某条记忆格式不对，丢掉那一条，其余照常导入，并告诉你丢了几条

### 回复长什么样

```
包：long_memory_20261024_150000_ab12cd.zip（3 人 / 42 条）
模式：覆盖
已备份当前数据 → pre_import_20261024_153100_replace.zip
结果：写入 3 人；删除本地 1 人（不在包内）
```

看到「删除本地 N 人」数字不对，立刻用备份包 `/导入 覆盖` 撤回。

## 配置项

绝大多数保持默认就行，加粗的是你可能想动的。

| 配置 | 默认 | 作用 |
|---|---|---|
| `enable` | 开 | 总开关 |
| `extract_enabled` | 开 | 是否从消息里学新记忆 |
| `inject_enabled` | 开 | 是否把记忆带进对话 |
| `max_items` | 30 | 每人最多存几条，超了按规则淘汰 |
| `inject_max_items` | 30 | 每次对话最多带几条进去 |
| `inject_max_chars` | 500 | 带进去的正文总字数上限 |
| `ttl_days` | 180 | 多久没被提到就忘掉，0 表示不过期 |
| `allow_group_cmd` | 关 | 是否允许在群里用 `/记忆` `/忘记` |
| **`panel_base_url`** | 空 | 面板地址，用来拼下载链接。**第一次用建议填上** |
| `export_token_ttl` | 3600 | 下载链接有效期（秒） |
| `export_keep` | 5 | 最多留几份导出包 |
| `export_ttl_days` | 7 | 导出包留几天 |
| `import_zip` | 空 | 上传的导入包，插件自己填 |
| `import_default_mode` | 覆盖 | `/导入` 不带参数时用哪种模式 |
| `import_backup` | 开 | 导入前是否自动备份 |
| `import_max_mb` | 32 | 单个导入包大小上限 |

> **从 0.2.1 升级上来的用户注意**
>
> AstrBot 会拿你**已保存的配置**覆盖代码里的默认值。升到 0.2.2 后，面板里的 `inject_max_items` / `inject_max_chars` 很可能还停在 `8` / `200`——那就等于没升级到「全量注入」。
>
> 请手动把这两项改成 **30** 和 **500**，保存后生效。

### 淘汰规则

每人上限 30 条，超了按这个顺序淘汰：

1. 先淘汰**不粘的**——喜好、厌恶、习惯可以被淘汰；称呼、住处、工作属于「粘性」信息，不淘汰
2. 再淘汰**没被反复提到的**——说过三次以上的变成常驻，不淘汰
3. 再淘汰**提到次数少的**
4. 最后淘汰**最久没更新的**

## 卸载与彻底删除

**第 1 步：先备份。** 私聊发 `/导出`，把包存好。

**第 2 步：卸载时勾选「同时删除插件持久化数据」。**

这一步不能省。卸载弹窗里有两个复选框，默认都不勾。不勾的话，插件代码删了，`data/plugin_data/astrbot_plugin_long_memory/` 里的记忆文件会原地留着。

**第 3 步：核对一眼。** 去 `data/plugin_data/` 看，里面不应该再有 `astrbot_plugin_long_memory`。

> **插件为什么不能自己删自己**
>
> 试过了，做不到。AstrBot 调插件 `terminate()` 的时机包括：卸载、禁用、重载、更新、进程退出——**五种情况调的是同一个函数，没有参数告诉你「这次是卸载」**。
>
> 在 `terminate()` 里删数据，等于你每次改个配置热重载一下，记忆就被清空了。更糟的是，插件已经被禁用时再点卸载，`terminate()` 根本不会执行。
>
> 所以这件事只能由你在卸载弹窗里勾。AstrBot 把开关放在那儿是有道理的。

> **不要改插件目录名**
>
> 卸载时删的是 `data/plugin_data/<插件目录名>`，而插件写数据用的是 `metadata.yaml` 里的 `name`（`astrbot_plugin_long_memory`）。两者默认一致。你要是把 `data/plugins/` 下的目录改成别的名字，勾了删除也删不到，只能手动删路径。

**不想卸载但想清空？** 私聊发 `/清空全部 确认`，一次删掉记忆、导出包、备份。

## 常见问题

**我明明说了喜欢什么，`/记忆` 里没有**

按可能性排查：

1. 一句话里有逗号，插件会分段看，可能只取到前半句
2. 带了数字——含 4 位以上连续数字的整句都不记（防手机号和地址）
3. 太含蓄——`不太能接受太酸的豆子` 记不住，要说 `我不喜欢太酸的豆子`
4. 太短——少于 4 个字的句子不看
5. 是疑问句——带「吗」「什么」「怎么」的不记

**`/记忆` 完全没反应**

- 在群里吗？群聊默认不许用，要开 `allow_group_cmd`
- 带目标了吗？查别人的记录要你的号在 `admins_id` 里，否则回一句「只能操作自己的记忆」
- 用 `@` 指定却没生效？确认 @ 的是真人而不是群里的重名文本；一次只能 @ 一个

**`/导出` 只回了一个相对路径**

没填 `panel_base_url`。填好再导一次，或者自己把面板地址拼在那个 `/api/file/...` 前面。

**链接打不开**

- 超过有效期了 → 重新 `/导出`
- AstrBot 重启过 → 重新 `/导出`
- 用了反向代理 → 确认 `/api/file/` 这条路径能通（它在免登录白名单里）

**`/导入` 说没找到 zip**

上传完没点保存。WebUI 的配置页是「上传到磁盘」和「保存配置」两个动作，只有后者会触发插件重载。

**`/导入` 说全都导入过了**

防重复机制在起作用，同一个包只认一次。要重导就重新上传一份，内容一样也算新包。

**她会不会把别人的偏好记到我头上**

不会。记忆按 QQ 号存，一人一个文件。但**同一个人**的私聊和群聊共享同一份记忆——设计如此，你在群里说过的话，私聊时她也记得。

**会不会拖慢回复、把上下文撑爆**

- 注入有 0.3 秒超时，读不到就直接跳过，不影响回复
- 默认把**最多 30 条 / 500 字**全部带进去（约 558 字符、300 个 token 上下），比一轮对话的历史小得多
- 这段内容是临时的，不写进对话历史，不会越滚越长

**升级插件会丢数据吗**

不会。更新和重装只替换 `data/plugins/` 下的代码，完全不动 `data/plugin_data/`。

## 它是怎么工作的

给想改代码、或者想确认它没干别的人看。

**注入时机**：每轮请求发给模型前，AstrBot 会触发 `on_llm_request` 钩子。插件在这里读出这个人的记忆，拼成一段 `<user_memory>` 文本，追加到用户消息后面。

**怎么挑条目**：先把称呼/住处/工作这三类（粘性信息）放最前，再把与本轮问句字面重合的提前，然后按命中次数和更新时间排。默认上限是 30 条 / 500 字，对绝大多数人来说等于**全部带进去**——所以「明明记着却想不起来」基本不会发生。

> 关于字面匹配的边界：问「我喜欢什么颜色」时，其实是被「蓝色」里那个**「色」字**蹭上的——纯属巧合。换成「我喜欢什么花」去问「喜欢吃苹果」，一个字都对不上。所以别指望它算得准，能答出来是因为**全部记忆都在上下文里**。

**为什么不塞进 system prompt**：system prompt 是所有轮次共享的前缀，每轮变化会打断模型的缓存，成本可能涨 7–20 倍。而且记忆是「参考材料」，不是「角色设定」，放用户侧更合适。这段内容带 `mark_as_temp()` 标记，不会被写进对话历史。

**抽取时机**：同一个钩子里，用正则从用户这轮说的话里找候选。不调模型、不联网、零延迟。抽到后开个后台任务写文件，不阻塞回复。

**为什么用正则不用模型**：调一次模型就多一次钱、多一次延迟，而且抽取本身也可能编。规则的好处是行为可预测——你说什么会被记、什么不会被记，能一条条讲清楚。

### 文件职责

| 文件 | 干什么 |
|---|---|
| `main.py` | 钩子、五个指令、导出链接 |
| `memory_core.py` | 抽取规则、去重淘汰、注入块生成、导入合并 |
| `store.py` | 文件读写、原子替换、备份、状态 |
| `transfer.py` | zip 打包与校验（所有安全限制在这） |
| `tests/` | 单测，`python tests/run_tests.py` 直接跑 |

改规则去 `memory_core.py` 里找 `_RULES`，每条是一个正则加一个渲染方式，照着加就行。

## 已知边界

- 只认固定句式。口语化、隐喻、反问一律记不住——刻意的取舍
- 每人 30 条上限。长期高频聊天的人可能触顶，靠淘汰规则保住最要紧的
- 不做语义检索。注入顺序是「粘性优先 → 本轮字面相关的优先 → 命中多 → 新的」，不是「跟这句话语义最相关的」；但默认配置会把全部记忆带进去，所以「记着却想不起来」基本不会发生
- 同一人私聊与群共享一份记忆
- 导出包含所有人的 QQ 和偏好，是敏感数据集
